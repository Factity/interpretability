GRAM — One Model That Can Forget on Command

I got the paper code and the blog post related to the work from ae studio and anthropic.

The author talks about the duality of ai use how it can be used maliciously. The talk about all the consequences of restricting model access and the need for training separate models and how it is not possible when giving access to labs working on bio, nuclear, cyber capabilities. His argument goes like this If a bio lab wants to develop a drug they need top tier model capabilities which can also be used to make bio weapons. Now training and serving separate models would be the gold standard but it is prohibitively expensive. To address this issue the have built gradient routed auxiliary modules gram for short. lets see how they have designed these.

a pretraining method that adds modules to a neural network and selectively updates them to induce specialization.

According to the experiments conducted by the lab it shows that the model is much more resistant to changes and shown to be more robust than unlearning mechanisms and fine tuning mechanisms. The say one of the major advantages of this approach is that this method scales very well.

They talk about an alternative approach to deploying N separate models in N different deployment environments. The method is model branching: train a base model on filtered data then split into separate variants by fine tuning each on different dual use capability.

Even with the above method we have serve them separately and lose out on most the capabilities that are learned during the pretraining at scale.

How do they intend to build the GRAM model?

Only in a single training run they intend to create multiple capability training profiles. By augmenting the MLP layers of a dense transformer with several smaller MLP modules. Then selectively enables forward and backward passes for different modules based on the data in the current training batch by directing capability specific updates to corresponding modules. During the inference they switch modules which selectively removes certain capabilities. According to their experiments that this method is vastly better than the post hoc unlearning in resisting malicious fine tuning.

What did the GRAM use?

  • Domain specific modules
  • data dependent gradient selective updates
  • Separate optimization process for parameter subsets

What are approaches they are comparing this against?

  • data filtering
  • model branching
  • post hoc unlearning

Background on how they have designed the engineering

They took $D = \{ D_1, \dots, D_N \}$ be the set of datasets and every set other than the first is the auxiliary capability dataset and $D_1$ is the general purpose data set and they also took a capability profile. In this first one being the base or the retain set and the forget set being $F = \{ 2,\dots,N \}$ as the auxiliaries to restrict.

The validation cross entropy loss is defined to be $\ell(M,D_{i})$.

Compute ratio metric

How do we compare the amount of training compute required for the different modules specified to do this they have introduced a metric called as compute ratio metric.

Definition: Let $M_{BL}$ denote a standard transformer block with dense MLP block trained on all the datasets $D_{all} = \bigcup_{i=1}^N D_i$. For each dataset they use a monotonic continuous power law learning curve $L_i(s)$ that maps baseline training step $s$ to baseline validation cross entropy loss at that step.

$$CR(M, D_i) = \frac{L_i^{-1}\big(\ell(M, D_i)\big)}{L_i^{-1}\big(\ell(M_{BL}, D_i)\big)}$$

A compute ratio of $r$ indicates that the model achieves a loss equivalent to the baseline after a fraction $r$ of the compute.

How do we evaluate the results?

For the forget sets lower compute ratios indicate better performance, and higher compute ratios indicate better performance for the core / retain set.

Architecture: a modular approach

Now that the metrics are out of the way lets look at how we are going to design the architecture of the model to enable this modular approach !!!

So they took a Transformer architecture and augmented each MLP block with smaller auxiliary MLP modules.

They are routing it based on data labels rather than per token or using a router.

The core module is almost the same size as the baseline transformer MLP Layer. Each of the auxiliary layer has the small fraction of the parameters of the base module. The intent is that the core module capture the general knowledge and the aux modules capture the specialized knowledge. Here we take the sum of the modules based on which of them are activated.

In a standard dense Transformer, each layer has an MLP $f_{\text{mlp}}: \mathbb{R}^d \to \mathbb{R}^d$. GRAM replaces this with a gateless mixture:

For layer $\ell$, define experts $E_0^{(\ell)}, E_1^{(\ell)}, \dots, E_{N-1}^{(\ell)}$ where:

  • $E_0^{(\ell)}$ is the core MLP with hidden dimension $d_{\text{core}}$.
  • $E_i^{(\ell)}$ for $i \geq 1$ is the auxiliary module for dataset $D_{i+1}$ with hidden dimension $d_{\text{aux}} \ll d_{\text{core}}$.

The layer output for input $x \in \mathbb{R}^{B \times T \times d}$ given forward mask $\mathbf{m}^{\text{fwd}} \in \{0,1\}^N$ is:

$$\text{MoE}(x; \mathbf{m}^{\text{fwd}}) = \sum_{j=0}^{N-1} m^{\text{fwd}}_j \cdot E_j^{(\ell)}(x)$$

Gradient Routing: how the training works

So you might be wondering if this is the case how should the gradients be updated how exactly the training process happens?

They used a method called as gradient routing for this. The forward pass depends on the dataset and the gradient updates over on the disjoint subsets as shown in the figure.

They picked 3 different metrics to decide which of the modules be active how they should be trained. They are

  • $p_{\text{as}}$ — Auxiliary spread (probability with which the core module is updated in backward pass)
  • $p_{\text{af}}$ — Auxiliary factor (decides which aux module is selected)
  • $p_{\text{cr}}$ — Core robustness (probability with which a random aux module gets activated)

Training the core batches

When training the core batches they took the dataset $D_1$ which is general purpose and trained it while activating one aux module with a probability of $p_{\text{cr}}$ in the forward pass. In the backward pass they just updated everything normally using the adamw optimizer.
Sample a batch $b \sim D_1$. With probability $p_{\text{cr}}$, sample a random auxiliary index $k \sim \text{Uniform}\{2, \dots, N\}$.

Forward mask:

$$m^{\text{fwd}}_j = \begin{cases} 1 & j = 0 \quad (\text{core always active})\\ 1 & j = k \quad \text{with prob. } p_{\text{cr}} \\ 0 & \text{otherwise} \end{cases}$$

Backward mask:

$$m^{\text{bck}}_j = \begin{cases} 1 & j = 0 \quad (\text{core always updated})\\ 1 & j = k \quad \text{if } m^{\text{fwd}}_k = 1 \\ 0 & \text{otherwise} \end{cases}$$

All active parameters are updated. The random auxiliary activation forces the core to remain robust to the presence or absence of any single auxiliary.

Training on the auxiliary data

When training on the auxiliary data they did a normal forward pass and while the backward pass they updated the core block with $p_{\text{as}}$. The selected aux $i$ is updated normally.

Sample a batch $b \sim D_i$.

Forward mask:

$$m^{\text{fwd}}_j = \begin{cases} 1 & j = 0 \quad (\text{core})\\ 1 & j = i \quad (\text{auxiliary } i)\\ 0 & \text{otherwise} \end{cases}$$

Backward mask:

$$m^{\text{bck}}_j = \begin{cases} 1 & j = i \quad (\text{auxiliary } i \text{ always updated})\\ \mathbb{1}[\text{Bernoulli}(p_{\text{as}})] & j = 0 \quad (\text{core updated with prob. } p_{\text{as}})\\ 0 & \text{otherwise} \end{cases}$$

When $p_{\text{as}} = 0$, the core is frozen and only $\Theta_{\text{aux}}^{(i)}$ learns $D_i$, maximizing modularity. When $p_{\text{as}} = 1$, the core absorbs auxiliary gradients, destroying modularity.

Function: memmap_write

Takes 3 input arguments, writes a memory‑mapped binary file.

  • np.memmap creates an array on disk, accessible like a NumPy array in memory.
  • mode="w+" creates/overwrites and allows read/write.
  • shape=(total,) – a 1‑dimensional array with exactly total elements.
  • File contains raw binary data (no headers), just numbers consecutively.
  • tqdm shows a progress bar for large datasets.
  • Each sub‑list a is assigned to the appropriate slice of the memory‑mapped array.
  • Advantage: saves to disk, doesn't load everything into RAM, faster writing.
def memmap_write(fname: Path, arr: List[List[int]], dtype: np.dtype = np.uint16) -> None:
    total = sum(len(a) for a in arr)
    mmap = np.memmap(fname, dtype=dtype, mode="w+", shape=(total,))
    idx = 0
    for a in tqdm(arr, desc="writing", total=len(arr)):
        mmap[idx : idx + len(a)] = a
        idx += len(a)
    mmap.flush()
prep function – summary

The prep function loads a dataset, optionally samples it, keeps only the required columns, performs a train-test split, and adjusts column names for clean file naming.

Input parameters
  • num_proc – number of processes that will run in parallel
  • tokenizer – an AutoTokenizer instance
  • max_length – maximum allowable sequence length
  • length_strategy – how to handle sequences exceeding max_length (truncate, drop, or none)
  • sample_pct – fraction of the dataset to use (0 to 1, default 1 = full, 0 = none)
  • column – name of the category column (e.g., story type)
Variable names
  • dset_name – name of the dataset to load
  • ds – the loaded dataset (obtained via load_dataset)
Section 1 – detailed workflow
  1. Dataset loading: The dataset dset_name is loaded into ds using load_dataset.
  2. Optional sampling: If sample_pct is less than 1, a random subset of that percentage is taken from the dataset using ds.select(...).
  3. Column selection: Only two columns are retained: story (the story text) and the column named by the input column (the story type).
  4. Train-test split: A simple train-test split is performed on the resulting dataset.
  5. Column name normalization: The text in the category column is modified for proper file naming (e.g., "Fairy TALES" becomes fairy-tales).

Cell 7 · Data loading

The BinShardDataset class wraps a memory‑mapped binary file (np.memmap) containing 16‑bit unsigned integer token IDs. It yields non‑overlapping chunks of length ctx_len as input‑target pairs:

  • Input: tokens [i : i+ctx_len]
  • Target: tokens [i+1 : i+ctx_len+1] (shifted by one for next‑token prediction)

The indices list precomputes start positions with a stride equal to ctx_len, ensuring no overlap between samples. build_loaders creates a dictionary of DataLoader objects for every combination of label (core + aux topics) and split (train/test). Train loaders are shuffled; test loaders are not. num_workers=2 enables multi‑process data loading, and pin_memory=True speeds up GPU transfers.

# =============================================================================
# DATA LOADING
# =============================================================================
class BinShardDataset(Dataset):
    def __init__(self, bin_path: Path, ctx_len: int = 256):
        self.ctx_len = ctx_len
        self.tokens = np.memmap(str(bin_path), dtype="uint16", mode="r")
        self.num_tokens = len(self.tokens)
        self.indices = list(range(0, self.num_tokens - ctx_len, ctx_len))
        if not self.indices:
            raise ValueError(f"Not enough tokens in {bin_path} for ctx_len={ctx_len}")

    def __len__(self):
        return len(self.indices)

    def __getitem__(self, idx):
        i = self.indices[idx]
        chunk = self.tokens[i:i + self.ctx_len + 1].astype(np.int64)
        return torch.from_numpy(chunk[:-1]), torch.from_numpy(chunk[1:])

def build_loaders(data_dir: Path, aux_topics: List[str], ctx_len: int, batch_size: int):
    labels = ["core"] + aux_topics
    loaders = {}
    for split in ["train", "test"]:
        for lab in labels:
            path = data_dir / f"{lab}_{split}.bin"
            if not path.exists():
                raise FileNotFoundError(f"Missing shard: {path}")
            ds = BinShardDataset(path, ctx_len)
            loaders[f"{lab}_{split}"] = DataLoader(
                ds, batch_size=batch_size, shuffle=(split == "train"),
                drop_last=True, pin_memory=True, num_workers=2
            )
    return loaders, labels

Cell 10 · Gradient freezing

freeze_module is a key utility for selective backpropagation. When do_freeze=True:

  1. All parameters of the module are detached (.detach()), breaking the gradient chain.
  2. The detached parameters and original buffers are stored in a dictionary.
  3. A callable is returned that uses torch.func.functional_call to perform the module’s forward pass with the detached parameters, so no gradients are accumulated for that module.

When do_freeze=False, the original module is returned unchanged. This allows the MoE and transformer blocks to selectively update only the experts that are active during a training step (governed by bck_mask), while the rest of the network remains frozen and contributes no gradient.

def freeze_module(module: nn.Module, do_freeze: bool):
    if not do_freeze:
        return module
    params_and_bufs = {
        **{n: p.detach() for n, p in module.named_parameters()},
        **{n: b for n, b in module.named_buffers()},
    }
    def call(*args, **kwargs):
        return torch.func.functional_call(module, params_and_bufs, args, kwargs)
    return call

Cell 12 · Core MLP and attention blocks

The following code cell defines two fundamental building blocks:

  • MLP – A standard two‑layer feed‑forward network with GELU activation (tanh approximation). It expands from embed_dim to mlp_dim and projects back. Used inside the mixture‑of‑experts.
  • Attention – Implements grouped‑query attention (GQA). Queries are projected to num_heads heads, while keys and values are projected to a smaller number of num_kv heads. Before scaled dot‑product attention, the key/value heads are repeated to match the query heads. Causal masking is applied by default via is_causal=True unless a custom mask is provided.

The use of GQA reduces memory and computation for the key/value projections, which is beneficial when auxiliary experts share the same attention block.

class MLP(nn.Module):
    def __init__(self, embed_dim: int, mlp_dim: int):
        super().__init__()
        self.c_fc = nn.Linear(embed_dim, mlp_dim, bias=True)
        self.c_proj = nn.Linear(mlp_dim, embed_dim, bias=True)

    def forward(self, x):
        return self.c_proj(F.gelu(self.c_fc(x), approximate="tanh"))

class Attention(nn.Module):
    def __init__(self, num_heads: int, embed_dim: int, num_kv: int):
        super().__init__()
        self.num_heads, self.num_kv = num_heads, num_kv
        self.head_dim = embed_dim // num_heads
        self.q_proj = nn.Linear(embed_dim, embed_dim)
        self.k_proj = nn.Linear(embed_dim, num_kv * self.head_dim)
        self.v_proj = nn.Linear(embed_dim, num_kv * self.head_dim)
        self.o_proj = nn.Linear(embed_dim, embed_dim)

    def forward(self, x, attn_mask=None):
        B, T, E = x.shape
        q = self.q_proj(x).view(B,T,self.num_heads,self.head_dim).transpose(1,2)
        k = self.k_proj(x).view(B,T,self.num_kv,self.head_dim).transpose(1,2)
        v = self.v_proj(x).view(B,T,self.num_kv,self.head_dim).transpose(1,2)
        if self.num_kv != self.num_heads:
            rep = self.num_heads // self.num_kv
            k = k.repeat_interleave(rep, dim=1)
            v = v.repeat_interleave(rep, dim=1)
        out = F.scaled_dot_product_attention(
            q, k, v, attn_mask=attn_mask, is_causal=(attn_mask is None)
        )
        out = out.transpose(1,2).contiguous().view(B,T,E)
        return self.o_proj(out)

class MoE(nn.Module):
    def __init__(self, embed_dim: int, num_experts: int, core_dim: int, aux_dim: int):
        super().__init__()
        self.experts = nn.ModuleList(
            [MLP(embed_dim, core_dim)] +
            [MLP(embed_dim, aux_dim) for _ in range(num_experts - 1)]
        )

    def forward(self, x, fwd_mask, bck_mask):
        y = None
        for i in range(len(self.experts)):
            w = fwd_mask[i].item()
            if w > 0:
                expert = freeze_module(self.experts[i], do_freeze=not bck_mask[i])
                out = expert(x)
                if w != 1.0:
                    out = w * out
                y = out if y is None else y + out
        return y

Cell 16 · Transformer block and GRAM model implementation

TransformerBlock combines attention and mixture‑of‑experts with pre‑norm RMSNorm. The core attention and normalisation layers can be frozen if the core expert is not being updated (freeze_core = not bck_mask[0]). This ensures that when only an auxiliary expert is trained, the shared attention parameters stay unchanged.

GRAMModel assembles the full model:

  • An embedding layer, NUM_LAYERS transformer blocks, final RMSNorm, and an unembedding (linear) projection to vocabulary size.
  • Initialisation follows a normal distribution with std=0.02, bias zero, and RMSNorm weight of 1.
  • The method get_params(label) returns the parameter groups associated with a given module label. For “core”, this includes the embedding, unembedding, final norm, and all attention/norm parameters across blocks. For an auxiliary label, it returns only the corresponding expert in every block’s MoE. This separates the optimisers so that different modules can be updated independently.
  • The forward pass applies masks; if no masks are given, all modules are active. Loss is standard cross‑entropy (ignoring index −100).
  • generate performs autoregressive sampling with temperature and optional top‑k filtering, respecting the module masks.

class TransformerBlock(nn.Module):
    def __init__(self, embed_dim, num_heads, num_kv, num_experts, core_dim, aux_dim):
        super().__init__()
        self.attn = Attention(num_heads, embed_dim, num_kv)
        self.moe = MoE(embed_dim, num_experts, core_dim, aux_dim)
        self.norm_1 = nn.RMSNorm(embed_dim)
        self.norm_2 = nn.RMSNorm(embed_dim)

    def forward(self, x, fwd_mask, bck_mask):
        freeze_core = not bck_mask[0].item()
        a = freeze_module(self.attn, freeze_core)
        n1 = freeze_module(self.norm_1, freeze_core)
        n2 = freeze_module(self.norm_2, freeze_core)
        x = x + a(n1(x))
        return x + self.moe(n2(x), fwd_mask, bck_mask)

class GRAMModel(nn.Module):
    def __init__(self, vocab_size, ctx_len, num_layers, num_heads, num_kv,
                 embed_dim, mlp_dim, core_mlp_prc, aux_mlp_prc, labels):
        super().__init__()
        assert labels[0] == "core"
        self.labels, self.ctx_len = labels, ctx_len
        align = 64
        core_dim = round(core_mlp_prc * mlp_dim / align) * align
        aux_dim = round(aux_mlp_prc * mlp_dim / align) * align
        self.embed = nn.Embedding(vocab_size, embed_dim)
        self.norm_f = nn.RMSNorm(embed_dim)
        self.unembed = nn.Linear(embed_dim, vocab_size)
        self.blocks = nn.ModuleList([
            TransformerBlock(embed_dim, num_heads, num_kv, len(labels), core_dim, aux_dim)
            for _ in range(num_layers)
        ])
        self.apply(self._init_weights)

    def _init_weights(self, m):
        if isinstance(m, (nn.Linear, nn.Embedding)):
            m.weight.data.normal_(mean=0.0, std=0.02)
            if getattr(m, "bias", None) is not None:
                m.bias.data.zero_()
        elif isinstance(m, nn.RMSNorm):
            m.weight.data.fill_(1.0)

    def get_params(self, label):
        idx = self.labels.index(label)
        if label == "core":
            yield from self.embed.parameters()
            yield from self.unembed.parameters()
            yield from self.norm_f.parameters()
        for block in self.blocks:
            if label == "core":
                yield from block.attn.parameters()
                yield from block.norm_1.parameters()
                yield from block.norm_2.parameters()
            yield from block.moe.experts[idx].parameters()

    def forward(self, tokens, targets=None, fwd_mask=None, bck_mask=None):
        if fwd_mask is None:
            fwd_mask = torch.ones(len(self.labels), device=tokens.device)
        if bck_mask is None:
            bck_mask = torch.ones(len(self.labels), device=tokens.device).bool()
        freeze_core = not bck_mask[0].item()
        h = freeze_module(self.embed, freeze_core)(tokens)
        for block in self.blocks:
            h = block(h, fwd_mask, bck_mask)
        logits = freeze_module(self.unembed, freeze_core)(freeze_module(self.norm_f, freeze_core)(h))
        loss = None if targets is None else F.cross_entropy(
            logits.view(-1, logits.size(-1)), targets.reshape(-1), ignore_index=-100
        )
        return logits, loss

    @torch.no_grad()
    def generate(self, tokens, max_new_tokens, fwd_mask, temperature=1.0, top_k=None):
        self.eval()
        for _ in range(max_new_tokens):
            idx_cond = tokens[:, -self.ctx_len:]
            logits, _ = self.forward(idx_cond, fwd_mask=fwd_mask,
                                     bck_mask=fwd_mask.bool())
            logits = logits[:, -1, :] / temperature
            if top_k is not None:
                v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
                logits[logits < v[:, [-1]]] = -float("Inf")
            tokens = torch.cat((tokens, torch.multinomial(F.softmax(logits, -1), 1)), 1)
        return tokens

Cell 18 · Training stage of the pipeline

The training process is controlled by a schedule that alternates between core‑only steps and core‑auxiliary combination steps:

  • get_mask converts a list of active labels into a tensor mask.
  • build_schedule creates a list of training steps. Half of the core steps (with probability robust_prc=0.5) randomly include one auxiliary expert for the forward mask but only the core expert is updated. The other half are pure core steps (forward and backward both core only). Then, for each auxiliary expert, a block of steps is added where the auxiliary is included forward and only that auxiliary is updated backward. The schedule is shuffled.
  • In train, a separate AdamW optimiser is created for each label using the parameter groups from get_params. For each step, a batch is drawn from the appropriate loader, the forward/backward masks are applied, loss is computed, gradients are clipped, and only the optimisers whose parameters received gradients are stepped. This ensures that the core and each auxiliary module are trained according to the schedule without interference.
  • The model checkpoint is saved as gram_stories_3aux.pt.
  • Evaluation (evaluate) loops over test loaders for core and aux topics, computes loss with the expected masks (core only, or core + the auxiliary), and prints per‑topic perplexity approximations.

def get_mask(labels, active, device):
    m = torch.zeros(len(labels), device=device)
    for lab in active:
        m[labels.index(lab)] = 1.0
    return m

def build_schedule(loaders, labels, aux_labels, robust_prc=0.5):
    n_core = len(loaders["core_train"]) // 2
    min_batches = min(n_core, *(len(loaders[f"{a}_train"]) for a in aux_labels))
    sched = []
    for _ in range(min_batches):
        if random.random() < robust_prc:
            a = random.choice(aux_labels)
            sched.append(("core", ("core", a), ("core",)))
        else:
            sched.append(("core", ("core",), ("core",)))
    for a in aux_labels:
        for _ in range(min_batches):
            sched.append((a, ("core", a), (a,)))
    random.shuffle(sched)
    return sched

# Training follows the schedule, computes loss, clips gradients, and steps
# only optimizers whose parameter groups received gradients.
def train():
    random.seed(SEED); np.random.seed(SEED); torch.manual_seed(SEED)
    loaders, labels = build_loaders(DATA_DIR, AUX_TOPICS, CTX_LEN, BATCH_SIZE)
    model = GRAMModel(VOCAB_SIZE, CTX_LEN, NUM_LAYERS, NUM_HEADS, NUM_KV_HEADS,
                      EMBED_DIM, MLP_DIM, CORE_MLP_PRC, AUX_MLP_PRC, labels).to(DEVICE)
    opts = {lab: torch.optim.AdamW(list(model.get_params(lab)), lr=LR,
            fused=(DEVICE == "cuda")) for lab in labels}
    schedule = build_schedule(loaders, labels, AUX_TOPICS)
    iters = {k: iter(v) for k, v in loaders.items()}
    step = 0
    while step < MAX_STEPS:
        random.shuffle(schedule)
        for dlab, fwd_exps, bck_exps in schedule:
            if step >= MAX_STEPS: break
            try: x, y = next(iters[f"{dlab}_train"])
            except StopIteration:
                iters[f"{dlab}_train"] = iter(loaders[f"{dlab}_train"])
                x, y = next(iters[f"{dlab}_train"])
            x, y = x.to(DEVICE), y.to(DEVICE)
            loss = model(x, y, get_mask(labels, fwd_exps, DEVICE),
                         get_mask(labels, bck_exps, DEVICE).bool())[1]
            loss.backward()
            grads = [p for p in model.parameters() if p.grad is not None]
            if grads: torch.nn.utils.clip_grad_norm_(grads, GRAD_CLIP)
            for lab in labels:
                if any(p.grad is not None for p in model.get_params(lab)): opts[lab].step()
            for opt in opts.values(): opt.zero_grad(set_to_none=True)
            step += 1
    Path("checkpoints").mkdir(exist_ok=True)
    torch.save({"model": model.state_dict(), "labels": labels},
               "checkpoints/gram_stories_3aux.pt")
    return model, labels

def evaluate(model, loaders, labels, aux_labels, device):
    model.eval()
    with torch.no_grad():
        for lab in ["core"] + aux_labels:
            fwd = ("core", lab) if lab in aux_labels else ("core",)
            total = 0.0; count = 0
            for x, y in loaders[f"{lab}_test"]:
                _, loss = model(x.to(device), y.to(device), get_mask(labels, fwd, device),
                                get_mask(labels, fwd, device).bool())
                total += loss.item(); count += 1
                if count >= 20: break
            print(lab, total / max(count, 1))
